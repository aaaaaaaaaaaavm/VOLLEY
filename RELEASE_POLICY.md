# Academic release and continuing development

The academic release is targeted for **Friday, 30 October 2026, evening**. This is a release target, not a claim that approval, similarity checking, submission or publication has already occurred. The release record will identify the actual timestamp and timezone.

The release must identify the exact report PDF/DOCX, manuscript/source, presentation, engineering evidence and visual assets by checksum, together with the exact repository commits and release tags. A manifest must distinguish project-created files, separately distributed raw solver assets, publisher-controlled references and external records that are actually available. The release becomes the cited academic record only after its applicable checks and real owner/institutional requirements are recorded.

After that release, **VOLLEY-thesis and VOLLEY-paper remain frozen as the academic record until a new paper issue is deliberately prepared**. Subsequent work must not silently replace the cited report, manuscript, native geometry, numerical outputs or source identities. Any necessary correction is documented as an identified correction or new issue with its own manifest and release identity; the earlier record remains traceable. A venue submission or acceptance is recorded only when it actually occurs.

**VOLLEY Main and VOLLEY Labs continue development through separately versioned work.** Each later geometry, model, programme study or visual package names its own configuration and evidence boundary. It must state whether it reproduces the academic reference, corrects it, or evaluates a successor. Historical negative findings and source captures remain available under their original identities.

The repositories stay available. This policy does not archive repositories, delete engineering history or authorize rewriting published Git history. A tag is recorded as published only after its remote identity and attached release assets have been verified.
