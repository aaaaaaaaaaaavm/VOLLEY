# ADR-026: the CAD is generated from parameters, not drawn

**Status:** Accepted · **Date:** 2026-08-10 · **Phase:** I · **Extends:** ADR-015 · **Supersedes the method of:** ADR-019

## Context

`cad/parameters.json` opens with a warning it has no power to enforce:

> *"Do NOT edit dimensions inside Fusion 360 — user parameters there are document-scoped and will
> silently drift across the nine documents."*

Gen1 through Gen4 are Fusion documents, so that sentence is the only thing standing between this
repository and drift. **Gen4 shows what it costs.** It exists only inside Fusion, has never been
exported, and its stations do not match the parameters every published number rests on — it
releases at s = 1200 mm over a 900 mm stroke where `analysis/` assumes 1500 mm over 1.5 m. That
is **P39**, and it is why the repository currently publishes renders of geometry that **no
committed file matches** (**P43**).

The choice was between exporting Gen4 — which its own gate forbids until the position-dependent
electromagnetic calculation exists — and generating a new generation from the parameters directly.

## Decision

**Gen5 is generated by `cad/build_gen5.py` from `cad/parameters.json`, using CadQuery 2.8.0,
emitting STEP into `cad/step/gen5/`.**

Nothing is drawn. The script reads the parameter file and nothing else, so the model is a
*function* of the parameters in the same sense `docs/BASELINE.md` is a function of the analysis
results. It matches **ADR-015**: derive, never paste.

**This does not open Gen4's export gate and does not supersede Gen4 as a design.** It supersedes
the *method*. Gen4 remains what `docs/GEN4_STATUS.md` says it is.

## Why generated is the right answer here, not a compromise

- **A generated model cannot drift.** The failure mode `parameters.json` warns about is
  structurally impossible when the geometry has one source.
- **It regenerates from a clean clone**, so the CAD is reproducible by a reader, which no Fusion
  document in this repository has ever been.
- **It is byte-stable.** Two consecutive builds are identical — verified, and the STEP header
  timestamp is normalised to a fixed epoch precisely so that "the geometry changed" and "the
  clock changed" cannot be confused.
- **It is checked against its own source.** `--check` reads the geometry back out of the built
  solids and compares **23 dimensions** to `parameters.json`: envelope, station positions,
  cassette dimensions, flange diameters, payload envelope, and the magnetic air gap. A generated
  model that is never measured is just a script that ran.
- **`cad/BUILD.json` and `check_artifacts.py`** guard the STEP against the parameter file, so a
  dimension changed without a rebuild is caught rather than shipped.

The self-check earned its place immediately: it caught **three errors on its first run** — a
longeron built to the roller-channel width instead of the track's overall width, a gate pin
extruded outboard because a CadQuery `XZ` workplane extrudes along −Y, and a check that called
the radiator standing proud of the top skin an error when `parameters.json` records it as
intended. **Two were geometry bugs and one was a bad check.** None would have been visible in a
render.

## The limitation, stated because it is not small

**Gen5 is a geometry and interface model, not a manufacturing model.**

No fillets. No chamfers. No fasteners. No harness routing. No tolerancing. No weld or joint
detail. Every part is the simplest solid that carries the right interfaces at the right stations.

**Do not send it to a machine shop.** Do use it to check fit, envelope, clearance and station
alignment — which is what the repository actually needs from CAD, and what a reader needs to
believe the numbers.

One derived value is flagged rather than read: `parameters.json` gives the Halbach array in
**assembly** coordinates (x = 230…570) while a sled document needs its **own** frame, so the
array is centred on the 488 mm sled. That centring is an assumption and is marked as one in the
module docstring.

## Consequences

- **Accepted:** the repository gains a committed, reproducible, self-checked CAD generation that
  matches its parameters, closing the gap P43 had to publish around.
- **Accepted:** CadQuery 2.8.0 and its OCC stack become a dependency of the CAD, though not of
  the analysis. `requirements.txt` records it as optional.
- **Unchanged:** Fusion remains authoritative for nothing. `analysis/*.py` is authoritative for
  mass and performance; `parameters.json` for geometry. Gen5 is downstream of both.
- **Open:** Gen5 has no assembly document. The eight sub-systems are generated independently and
  their relative placement is implied by the shared coordinate frame rather than asserted by a
  joint model.
- **Open:** the renders in `cad/renders/` are still **Gen4**, so the published pictures and the
  committed geometry are two different generations. That is recorded in P43 and is not closed by
  this ADR.
