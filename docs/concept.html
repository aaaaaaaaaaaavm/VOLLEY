concept

Who should own the first few metres per second?

VOLLEY moves one narrow capability boundary: some initial mobility may be supplied by the host-side deployment system instead of being repeated on every spacecraft.

functional split

Three systems. Three responsibilities.

Host

Coarse orbital state, navigation, attitude authority, permitted manoeuvres, campaign resources, recoil recovery and disposal.

Deployment system

Retention, commanded relative release velocity, direction, timing, tip-off and mechanical interface.

Spacecraft

Everything after contact ends. VOLLEY does not provide continuing stationkeeping, formation control or collision avoidance.

real hardware context

The host-side idea is not science fiction. The VOLLEY mechanism is still unproven.

Spent upper stages have already been operated as controlled orbital platforms, and launch vehicles already manage large multi-satellite separation campaigns. Those facts motivate the host boundary; they do not demonstrate compatibility with VOLLEY.

ISRO · POEM-4

A spent PS4 used as a controlled orbital platform

Real upper-stage hardware with payloads assembled. This is host precedent, not a VOLLEY accommodation claim.

ISRO · LVM3-M2

A real 36-satellite separation campaign

Multi-satellite release, vehicle reorientation and safe separation are already launch-vehicle mission problems. VOLLEY asks whether more departure authority is worth adding.

what it is not

A release impulse is not a miniature transfer vehicle.

Position does not jump

Release changes velocity at the release position. A propulsion-less payload does not appear in an arbitrary new circular orbit because the deployer supplied extra speed.

Higher speed is not automatically better

Timing, direction, terminal-state error, host manoeuvres and conventional release sequencing can all compete with extra release authority.
